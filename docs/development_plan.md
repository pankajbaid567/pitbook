# Development plan and status

Checklist style (as in cache-cluster). An item is ticked only when the exit criterion for it is met by a command that can be re-run. The whole project was built in one continuous push on 2026-11-10; the effort estimates from the original plan are dropped.

## Phase 0: scaffold and decisions
- [x] Go module, Makefile, CI, license, editor config
- [x] `prd.md`, `architecture.md`, `DESIGN.md` (ADR-000 to ADR-017), `protocol.md`, `testing.md`, `benchmarks-method.md`, `deploy.md`, `resume-claims.md`
- [x] Name collision search recorded; renamed Bourse to Pitbook (ADR-000)

## Phase 1: core book
- [x] Types, limit / market / IOC / FOK / cancel / replace, price-time priority, self-trade prevention (ADR-004)
- [x] Hand-computed example tests for every rule
- [x] Naive reference matcher and property test: 1,000,000 random commands, identical events, invariants after every command
- [x] Mutation check: 5 injected bugs, all caught (`scripts/mutation_check.sh`)
- [x] Benchmark of `Book.Apply` (`BenchmarkSteadyMix`)

## Phase 2: sequencer and determinism
- [x] Binary command codec, `FuzzDecodeCommand`
- [x] Per-symbol engine goroutine, bounded queue with `ErrBusy`, group commit
- [x] `(seq, idx)` event ordering, machine state hash
- [x] `cmd/replay` prints the state hash; determinism test replays 20 to 25 times

## Phase 3: WAL, snapshots, recovery
- [x] CRC-framed segmented WAL, sync / async modes, torn-tail truncation, corruption refusal (`FuzzOpenNeverPanics`, cut-at-every-byte test)
- [x] Atomic snapshots, fallback to the previous one, WAL trimming after a snapshot
- [x] Idempotency table in the state machine and snapshots (ADR-011, ADR-015)
- [x] `cmd/crashtest`: 1,000 SIGKILL runs, 0 failures, harness itself validated by breaking the server on purpose
- [x] A real bug found and fixed by the harness (ADR-015)

## Phase 4: gateway, bots, UI
- [x] REST + WebSocket gateway, contiguous frames with gap detection, slow-consumer resync, rate limits, CORS and origin checks, `/healthz`, `/metrics`, `/v1/stats`
- [x] Seeded demo bots, bounded book
- [x] React UI: ladder, depth chart, tape, order entry, live stats, crash-recovery panel, recorded-session fallback, verified-results panel
- [x] Recorded feed generated by `cmd/genfeed` from the real engine

## Phase 5: benchmarks and hardening
- [x] Open-loop `cmd/loadgen` with fixed schedule and seeds; saturation, headline and secondary workloads; recovery timing
- [x] `scripts/make_benchmarks.py` generates `BENCHMARKS.md` from raw CSV
- [x] Allocation and GC measured; decision to skip a pooled allocator recorded (ADR-005)
- [ ] Re-run the matrix on an idle machine (the recorded runs were on a busy laptop; see `benchmarks-method.md`)

## Phase 6: deploy and polish
- [x] Dockerfile (distroless, non-root), `render.yaml`, archive mirror and restore (`internal/archive`, store Worker, R2 bucket)
- [x] Resume claims register audited against the repo (`docs/resume-claims.md`)
- [x] Pushed to GitHub; Render service `pitbook-demo` live; UI Worker live
- [ ] Enable the object-store mirror on Render (owner sets `ARCHIVE_TOKEN`), then the cold-start and crash-button check from `deploy.md`
- [ ] Confirm the first GitHub Actions run is green

## Future work (explicitly not v1)
Post-only and stop orders; auctions; per-participant risk limits; replication via Raft on top of the deterministic core (a natural follow-up to cache-cluster); a binary market-data feed; expiry of old idempotency entries; a Go-vs-Rust comparison of the book; Linux `fdatasync` benchmark on NVMe.
